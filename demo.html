The journey

Split the monolith into subgraphs, one entity at a time

Today

A monolithic MonoGraph schema, plus BFF REST endpoints that fan out to several services by hand.

→

Registry

Every entity, type, operation and auth scope in GQLRegistry.xlsx, with owners, approval status and links.

→

Target

Federated subgraphs joined by @key. The router answers one query from several subgraphs.

  • Generate the subgraphs from each service's OpenAPI spec, and check them against the MonoGraph.
  • Govern every change: Draft → Proposed → Approved, checked against the schema standards.
  • Migrate the callers: REST and BFF endpoints become FedGQL client and server code.

See the supergraph the registry describes

Code migration · subgraph-codemigration.html

REST call in, FedGQL client or server code out

  • Load the registry and the service's REST spec. Current Reference pairs each REST operation with its GraphQL operation.
  • Client: JavaScript, Java, Android (Kotlin), iOS (Swift).
  • Server: Spring for GraphQL, .NET Hot Chocolate, Apollo Server.
  • REST and FedGQL shown side by side, with renamed fields highlighted.
// Current — REST (GET /products/{sku})
const res = await fetch(`${BASE}/products/${sku}`);
const product = await res.json();
// Target — FedGQL
const query = `query Product($sku: String!) {
  product(sku: $sku) { sku title imageUrl brand }
}`;
const { data } = await post(GRAPHQL_URL, { query, variables: { sku } });

Code migration · orchestrating mutation

Checkout: one mutation, orchestrated

  • The router runs mutation fields one after another, but one field can't use the previous field's result.
  • Pick submitCheckout as the orchestrating mutation. The other ops become its steps: cart → inventory → payments → clear cart.
  • You get the one mutation the client sends, a resolver skeleton with compensation on failure, and a Mermaid sequence diagram.
  • Single ops get a sequence trace too: router → subgraph → _entities by @key.

Get started

End to end in eight steps

  1. Workbench: load the registry, or Load example.
  2. Add the target entities: domain, application, links.
  3. GQL migration: pick the entity and import its OpenAPI spec.
  4. Compare with the MonoGraph and assign its types.
  5. Edit the rows and set them to Proposed.
  6. Copy to the GQL Registry, then review and approve.
  7. Export, or Save & push to SharePoint or Drive.
  8. Code migration: generate the REST/BFF → FedGQL code.
