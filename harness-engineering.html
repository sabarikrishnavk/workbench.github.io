Each step: ▶ Start copies the skill's pinned prompt, which you run in Claude Code. Record output takes the artifact reference (or the handoff envelope the agent prints) and the gate results. Approve emits the artifact's event, and every skill whose required inputs are now all approved moves to Ready. Reopen on an approved step marks everything downstream stale, so it has to run again.

Graph memory sync

Every approved artifact is queued for the memory steward (/sync-graph-memory), which upserts its nodes and edges into the common graph. Reopening an artifact queues a retract. The Graph memory tab shows the full process.

From manual triggers to an orchestrator

The catalog is already a workflow definition: skills are tasks, artifacts are typed messages, an approved artifact's event is the trigger, gates are deterministic checks that run outside the model, and approval is a human wait state. Every phase below runs the same definition. Only the thing that moves the events changes.

Orchestrator options

The highlighted row is the recommendation for a multi-week SDLC with human approvals, parallel work items and reruns. For the agent runtime inside each task, use the Claude Agent SDK (or headless Claude Code) whichever engine you choose.

Repository scaffold

A harness layout modelled on OpenAI's Harness engineering. AGENTS.md is a short map, knowledge lives in docs/ (design-docs, exec-plans, generated, product-specs, references, PLANS.md, QUALITY_SCORE.md), and alongside it are templates/artifacts, .claude/agents, .claude/skills and a template checker. It's generated from the master data, so a new skill, agent or artifact is wired into every file that mentions it. ● marks files that differ from your last download.
