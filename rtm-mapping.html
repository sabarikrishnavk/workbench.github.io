    Lineage by high-level requirement

    High-level requirement

    Requirement → detail requirements → high-level design (applications and interfaces) → detail design (data-mapping interfaces, datasets, attributes, mappings, events). Click a box to highlight its path; click it again to clear.

    Applications & interfaces impacted end to end

    Each box is an application, placed by layer (core → integration → domain → router / BFF → front end); each line is an interface (data-mapping flow) the requirement touches, coloured by its change. Internal flows (database → API, outbox → topic) are counted inside the box.

    Attribute data lineage

    Every changed or verified attribute, traced upstream to its source and downstream to its last consumer through the Data mapping registry plus the new mappings in the design. new marks a designed mapping that is not in the registry yet, chg a mapping the design changes and retired one it retires.

    HLR

    Coverage by high-level requirement

    A detail requirement is designed when a high-level design row covers it, and detailed when every one of those rows has at least one detail-design artifact.

    Registry checks

    Broken references, requirements without design, design rows without detail, artifacts that are not in the Data mapping registry, artifacts outside their component, and interfaces whose applications are not in the design.
